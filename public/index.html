What stays with us

Memory belongs to Dyanari and is shared across all chat models. Switching models preserves saved memories, personality and stored conversations. Project boundaries and private-session rules still apply.

Memories are editable and use local semantic retrieval. Begin a message with “Remember that …” to store an explicit fact. Project memories are recalled only in the selected project; unlabelled memories are shared.

Memory suggestions

Off by default. Simple local rules propose preferences and project facts from your messages. Suggestions are not recalled as saved memories until you approve them. Private messages are excluded. Workflow preferences never grant tool permissions.

Review related memories

Similar wording can describe different or conflicting facts. Review the originals and choose the corrected text before consolidating. Projects cannot be merged together.

Research & source notebook

Ask in the main chat: “Research Iron Warriors Space Marines, explain their history and appearance, and retain the sources for later images.” Google runs in a separate background browser; readable source excerpts are stored locally, independently of the chat model. Internet Access must be ON. Private research is not retained.

Saved information is dated evidence, not permanent truth or model training. Ask for refreshed research when facts may have changed. Image prompts should use supported visual details; generated images still need inspection.

Permission is yours

Both master switches default to OFF. File access is restricted to approved folders. File deletion requires explicit confirmation in Activity and moves the file to recovery storage. Computer actions and offline project checks have separate permissions in Computer & checks. Arbitrary shell commands are unavailable.

Requires Tools, Read Files and Run Tools. Tasks retain your original request and tool results separately from chat. These are persistent work records, not private conversations. Existing file/execution/GitHub/MCP permissions still apply.

        
        
        
        
        
        
Execution approvals remain in Development or Linked projects. A task never approves its own commands or writes. Stop, restart or settings changes pause work; inspect partial results before resuming. “Finished” means the model ended its turn, not independent proof of correctness.
